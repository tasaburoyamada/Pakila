# 型システムおよび状態遷移設計書 (Type System & State Transition Specification)

## 1. 概要
Pakila は Lean 4 の依存型および強力な型システムを活用し、AI エージェントの状態遷移と副作用（IO, FFI, API 通信）をモナドレベルで厳密に型付け・制御します。

---

## 2. モナドスタックおよび型アーキテクチャ

### 2.1. コアモナド (`Pakila.Core.Monad`)
Pakila の実行パイプラインは、以下のコンポーネントを統合するモナド層で構成されます。
- `PakilaM`: 大域状態 `State` の更新、環境変数 `Env` の参照、およびエラーフォールバックを行う基幹モナド。
- `ExceptT AppError`: 実行時エラーの型安全な捕捉。
- `StateT PakilaState`: 会話履歴、セッションコンテクスト、コンフィグ状態の追跡。

### 2.2. エラー型体系 (`AppError`)
エラーの曖昧なスローを排除し、決定論的フォールバックを保証します。
- `AppError.ExecutionError`: サンドボックス / FFI 実行時の障害。
- `AppError.ProtocolError`: API 通信またはレスポンススキーマ不適合。
- `AppError.ConfigError`: 設定読み込み障害。

---

## 3. 状態遷移マシン (`Pakila.Core.Machine` / `Pakila.MainLoop`)

### 3.1. メインループ契約
`nomos` の `Agent` トレイト契約に従い、以下のループで決定論的に状態遷移が実行されます。

1. **入力受付 (`InputPhase`)**: ユーザー入力および CLI 引数のパースと Symbol32 正規化。
2. **コンテクスト生成 (`ContextPhase`)**: VectorDB 参照および ContextLoader による動的プロンプト構成。
3. **推論実行 (`InferencePhase`)**: Lyceum を経由した Gemini / GGUF モデル呼び出し（並列ツールコール・思考プロセス含む）。
4. **アクション実行 (`ActionPhase`)**: Wasmtime サンドボックスまたは Dispatcher モナドによる安全な並列アクション実行。
5. **状態更新・永続化 (`StateUpdatePhase`)**: 履歴保存および永続化層への反映。

---

## 4. 物理境界と防腐層 (Anti-Corruption Layer)
- **Stdio / IO 境界**: `TerminalEnv` により物理標準入出力 EOF およびシグナル制御を決定論的に保護。
- **FFI 境界**: C/Wasm 境界においてポインタ生値を直接扱わず、明確にシリアライズされたバイト配列と静的ハンドラでカプセル化。
