# Pakila 開発経緯

## 1. 開発動機：Rust からのさらなる飛躍と検証性の追求
本プロジェクトは、先行プロジェクト `Lasada`（Rustベース）の成果を土台としつつ、「自律エージェントの決定論的な安定性」を極限まで高めるために開始されました。

*   **Rust 版での課題**: Rust はメモリ安全性とパフォーマンスにおいて卓越していましたが、大規模で複雑な自律ループ（再帰的な推論と実行）において、論理的な不変条件をコンパイル時に完全に保証することには限界がありました。
*   **数理的検証の必要性**: AI が自律的にコードを生成・実行する過程で、システムの状態が矛盾に陥らないことを「証明」できる基盤が求められました。

## 2. 技術的解決：Lean 4 による数理的再構築
「プログラムは定理であり、実行は証明である」という哲学を具現化するため、定理証明支援系を内蔵する汎用プログラミング言語 Lean 4 を選択しました。

*   **純粋関数型コア**: 副作用を伴う実行エンジンと、ピュアな状態遷移ロジックを型レベルで分離。これにより、インタプリタの主導権を人間が「数理的に」握り続けることを可能にしました。
*   **環境界面の徹底ガード**: 「Lean にバグは無いが環境との界面にはバグが潜む」という洞察に基づき、OS コマンド、プロセス、I/O に対する物理的な防御（タイムアウト、リソースリミッター、例外の強制トラップ）を Lean 4 上に構築しました。

## 3. 実装された主要機能
`Lasada` の機能を継承しつつ、Any-To-Any マルチモーダル対応という新たな地平を切り拓きました。

*   **Any-To-Any マルチモーダル・パイプライン**: テキストだけでなく、画像、音声、動画、ツールコールを透過的に扱う多相的メッセージ構造を実装。Gemini 1.5/2.0 等の最新 API 能力をフルに活用可能です。
*   **ハイブリッド・モデルレジストリ**: クラウド（Gemini）とローカル（GGUF）のモデルを自律的に発見・検証し、環境に合わせて最適な推論を継続します。
*   **自己修復自律ループ**: AI が生成した Markdown コードブロックを抽出し、物理環境で実行した結果をフィードバックする再帰的推論プロセスを定式化しました。

## 4. 結論
Pakila は、単なる「動く道具」から「正しさが保証された知能」への転換点です。Lean 4 の厳格な論理性と HV-CAD の柔軟な統治を融合させることで、不確実な現実環境においても、人間の価値観に忠実かつ決定論的に振る舞い続ける自律エージェントを実現しました。
