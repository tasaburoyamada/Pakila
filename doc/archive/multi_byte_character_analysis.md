# マルチバイト文字（日本語）入力不具合に関する調査報告

## 調査概要

本報告書は、CLIアプリケーションにおける日本語入力不具合の原因究明に向けた調査結果をまとめたものです。

## 調査結果

プロジェクト全体で、エンコーディング、Unicode、UTF-8、国際化（i18n）、ローカライゼーション（l10n）、ロケール、文字セットなどに関連するキーワードでコードベースを検索しましたが、直接的な一致は見つかりませんでした。

これは、問題が特定のファイル名やキーワードに紐づくものではなく、より低レベルのターミナルI/O処理、またはOS/ターミナル環境とのインタラクションに起因している可能性が高いことを示唆しています。

これまでの調査で特定された、マルチバイト文字（日本語）の処理に問題がある可能性が最も高い箇所は以下の通りです。

### 1. `Pakila/Core/Environment.lean` における `TerminalEnv` の `IO` 実装

*   **`readChar` 関数:**
    *   ネイティブ関数 `getCharNative () : IO UInt8` が、ターミナルから1バイトずつしか読み取らず、日本語のようなマルチバイト文字を正しく構成できない可能性。
    *   `Char.ofNat b.toNat` による変換が、単一バイトを前提としており、マルチバイト文字の途中バイトを誤った文字として解釈する原因となる可能性。

*   **`enableRawModeNative` / `disableRawModeNative` 関数:**
    *   RAWモードの設定が、ターミナルの文字コード設定に影響を与えるか、またはRAWモード自体がマルチバイト文字のバッファリングや解釈を妨げる可能性。

### 2. `Pakila/CLI/Terminal.lean` における `readLineWithHistory` 関数

*   **文字処理ループ:**
    *   `while loop do let b ← TerminalEnv.readChar` の部分で、`readChar` から得られたバイトを `Char` に変換する際に、マルチバイト文字のバイトシーケリン​​グを正しく扱えていない可能性。
    *   マルチバイト文字を正しく組み立てるための具体的なロジック（例: UTF-8デコーディング）が欠けている可能性。

## 結論

現時点での分析に基づくと、問題の根本原因は、`pakila` アプリケーションが使用しているカスタムターミナルI/O (`TerminalEnv`) のネイティブ実装部分（特に `getCharNative`）に存在すると強く推測されます。これは、ターミナルからの入力をバイト単位でしか処理せず、マルチバイト文字のバイトシーケンスを正しく組み立てて `Char` や `String` に変換するロジックを持っていないためです。

これらの箇所が、マルチバイト文字（日本語）に直接対応していない、あるいは対応が不十分な部分となります。

現段階では、これらの箇所が「原因となっている可能性が最も高い」と考えられます。ネイティブコード自体の詳細なデバッグや、ターミナルの具体的な環境設定（`LANG`, `TERM` など）の確認までは行えていません。
